# 设计说明

[English](./DESIGN.md) · **简体中文**

本 fork 在[上游](https://github.com/RUIIIOVO/paseo-usage-sidebar)之上加了什么，以及为什么这样做。
安装与使用见 [README](../README.zh-CN.md)；这里讲套餐归属、按账号去重、主机群仪表、节奏，以及仪表的折叠。

## 这是谁的套餐

面板里每个服务商的行头左边是这是谁的套餐，`Claude (you@example.com)`，右边是哪一档套餐，`Max 20x`。

Paseo 0.11 起会把按账号区分的行命名为 `Source (account)`，所以邮箱直接取自行名
（`shared/usage/account.ts`），不为此读取任何文件。行名里不带账号的服务商就不显示邮箱。

### 每个账号只留一块

知道账号也能合并重复项：同一份订阅无论在哪里登录，上报的数字都是同一份，所以解析到同一账号的两个服务商只渲染
成一块，而不是把同一个读数画两遍。读不到账号的行从不合并——未知不等于同一个账号。

### 侧边栏显示整个主机群

Paseo 客户端可以同时连着多台主机，每台都跑着自己的一份本插件。Paseo 会把这些副本的侧边栏项合并成一行，并且只
挂载其中一台主机的副本：当前路由所在的主机，否则是面板主机菜单里上次选的那台，否则是第一台。不做处理的话，仪表
就只会显示那一台主机。

所以仪表自己去读每一台在线主机，直接问各自的守护进程（`getPaseoClient(id).providers.listUsage()`），再按账号
合并成每个账号一块（`shared/usage/fleet.ts`）。先问 Paseo 挂载的那台主机；每个账号取第一个正常的读数，所以被限
流或出错的主机会把它的账号让给正常的那台。读不到的主机直接跳过。每个应用只看得到它连着的主机：连着虚拟机的笔记
本也会显示虚拟机上的账号，而虚拟机自己的应用只显示它自己。

面板仍然按主机显示：它的主机菜单决定显示谁的读数。

### 每个应用一套固定项

固定项指的是服务商 id 加窗口（`claude:weekly`），不是账号，所以在主机群仪表上，它会为每个上报该窗口的账号各显示
一行。固定项属于应用而不是某台主机：每台主机的副本都读写渲染进程 `globalThis` 上的同一个存储，并保存到
localStorage（`client/selection/store.ts`）。每次修改也会写进面板所在主机的状态文件；应用自己还没有固定项时（全
新安装，或没有 localStorage 的手机），用找到的第一台有固定项的主机来初始化。

## 侧边栏仪表的分组标题

这些行按服务商和它们所计入的账号分组——`Claude · you@example.com`。邮箱放在后面，因为它是省略号最先吃掉的
部分：在这个宽度下，服务商名称才是让下面那几行读得懂的东西，而邮箱是你已经知道名称之后用来区分两份套餐的。

每个分组标题同时也是一个折叠开关。点击它——或在聚焦后按 Enter / 空格——即可收起该账号下的所有行，行尾的
箭头会跟着变。折叠状态只存在于渲染进程里：它能挺过 60 秒一次的重绘和侧边栏重新挂载，但重载后即回到展开。

仪表由插件自己的侧边栏条目绘制在该行下方，所以在「设置 → 侧边栏」里随条目一起移动和隐藏。点击标题只会折叠；
标题下的各行会打开用量面板。

## 节奏

百分比只说掉了多少，说不了这算不算多——那完全取决于窗口自己走到了哪一步。数字旁边的 `▲12%` 表示比时间
快了 12 个百分点：窗口只过去了 45%，却已经用掉 57%。进度条上的那一小竖是「如果完全踩着时间走，填充
应该停在哪里」，所以竖线与填充边缘之间的距离，就是箭头那个数字画出来的样子。

| 读数 | 含义 |
| --- | --- |
| **▼ 绿** | 慢于时间。照这个速度，窗口重置时还有余量。 |
| **▲ 橙** | 快 1–5 个百分点。值得知道，但不值得为此改计划。 |
| **▲ 红** | 快出 5 个百分点以上。速度不降下来，这个窗口会提前用完。 |

与时间相差不到 1 个百分点时什么都不显示。已过去的比例每一秒都在走，已用掉的比例却只在你消耗时才动；
没有这条死区，每条进度条都会因为零点几个百分点的偏差而不停闪箭头，信号也就不再有意义。

已过去的比例是从重置时刻倒推出来的——守护进程只报窗口什么时候重置，从不报它什么时候开始、一共多长：
`five_hour` 是 5 小时，`weekly` 和 `weekly_<model>` 是 7 天，`daily` 是一天，`monthly` 是真正的日历月
（3 月 1 日重置就往回倒 28 天，而不是固定 30 天）。id 本身说不出周期的窗口（`coding_limit_*`、
`interval_*`，以及各服务商自定义的 id）不画箭头也不画竖线，而不是按猜出来的周期硬算一个。

面板顶部的 **Pace** 按钮可以在两个界面同时关掉整个读数。这个选择与固定集合一起存在
`$XDG_STATE_HOME/paseo-usage-sidebar/selection.json` 里，默认开启。两者分开写入、在服务端合并：所以切换
节奏箭头不会把默认固定集合固化成显式的那一份，重新排序也不会拿一份过期的开关值覆盖更新的值。

### 为什么箭头可以是绿色

进度条刻意不用绿色。绿色读作「良好」，等于把眼睛唯一的强信号花在了根本不需要注意的状态上；蓝色才是中性的
「这里没你的事」，这样暖色就只表达一件事。

插件里唯一的绿色，是节奏箭头的「慢于时间」。节奏是双向读数，而单向色阶没有一个颜色表示它好的那一端；
但绿色箭头放在蓝色进度条旁边，不会像绿色填充那样被误读成色阶的一部分。快于时间的两档沿用色阶自己的
橙和红，于是箭头和它下面的进度条按同样两个颜色升级。

## 隐私

Paseo 插件在设计上就没有沙箱，所以在信任任何一个插件之前都值得读一读。本 fork 改变的是上游从磁盘读取的内容；
其余与上游一致。

- **服务端代码** 运行在守护进程的子进程里，只调用一个 SDK 方法 `paseo.providers.listUsage()`。不做任何
  其他守护进程操作，也不自己开 socket。
- **不读取、不存储、不传输任何凭据。** 账号邮箱取自 Paseo 已经上报的行名，不打开任何登录文件。
- **没有新增的网络访问。** 仪表通过 Paseo 已经连着的连接向其他主机要用量；插件自己不打开任何 socket。
- **两处写入，都是你自己的**——固定集合和显示选项，写在每台主机的状态文件和应用的 localStorage 里。里面只有服
  务商 id、窗口 id 和两个显示设置：没有 token，没有用量数字，没有任何可识别账号的内容。

## 本 fork 新增的文件

```
client/selection/store.ts       # 每个应用一套固定项，所有主机的副本共用
shared/usage/account.ts         # 从 Paseo 行名取套餐归属，并按账号去重
shared/usage/account.check.ts   # 它的自检——账号键与去重规则
shared/usage/fleet.ts           # 合并所有主机的读数，每个账号一块
shared/usage/pace.ts            # 消耗与时间的对比：已过去比例、差值、阈值
shared/usage/pace.check.ts      # 它的自检——本仓库唯一带算术的模块
```

这些自检是纯断言，早于上游的 `npm test`。改了哪块就跑哪块旁边的那个，同时跑 `npm run typecheck` 和
`npm test`：

```bash
npx tsx shared/usage/pace.check.ts      # 节奏算术
npx tsx shared/usage/account.check.ts   # 账号键、按账号去重
```
